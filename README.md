# Своя игра: швейцарская жеребьёвка

Веб-приложение для проведения турнира по «Своей игре»: 4 отборочных тура по швейцарской системе и финал для тройки лучших. Бои на 3–4 участника, за 4 тура никто не встречается с одним соперником дважды.

Работает без интернета, сервера и установки зависимостей.

## Как пользоваться офлайн

### Вариант 1. Один файл — переслать и открыть
Файл [`dist/svoyak-zherebyevka.html`](dist/svoyak-zherebyevka.html) (≈260 КБ) содержит всё: приложение, алгоритм, шрифты.

1. Скачайте его (на странице файла — кнопка «Download raw file»).
2. Пересылайте как обычный файл: мессенджер, почта, флешка.
3. Открывайте двойным щелчком в любом браузере (Chrome, Edge, Firefox, Safari). Интернет не нужен.

Лучше всего подходит для ноутбука судьи. На телефоне удобнее вариант 2.

### Вариант 2. Установить как приложение
Если для репозитория включён GitHub Pages, приложение доступно по адресу `https://nikolajkatele2.github.io/svoyak-zherebyevka/`. Откройте его один раз с интернетом:

- **Android, Chrome:** меню ⋮ → «Установить приложение» (или кнопка «Установить приложение» в шапке).
- **iPhone, Safari:** «Поделиться» → «На экран „Домой“».
- **Компьютер, Chrome или Edge:** значок установки в адресной строке или кнопка в шапке.

После этого приложение открывается с иконки и работает без сети. Обновления подтягиваются сами, когда устройство снова в сети.

### Автосохранение в файл (Chrome, Edge, Яндекс Браузер на компьютере)
1. Положите `svoyak-zherebyevka.html` в отдельную папку, например «Турниры», и откройте его.
2. Нажмите **«Новый турнир»**, введите название → **«Создать»**. В первый раз браузер попросит выбрать папку: выберите ту же папку и разрешите запись.
3. В папке появится `Название.json`. Любое изменение — участники, жеребьёвка, баллы, перестановки, финал — сразу записывается в этот файл. В шапке видно: «Записано в „…json“ · время».
4. После перезапуска браузера он спросит разрешение на запись ещё раз: нажмите **«Продолжить»**. Приложение сверит файл с данными браузера и откроет более свежую версию. Если браузер предложит «Разрешать при каждом посещении», можно согласиться, тогда вопрос пропадёт.
5. На вкладке «Участники» — список всех турниров в папке с кнопкой «Открыть».

Если что-то случилось со страницей или браузер очистил данные, просто откройте приложение снова: турнир подхватится из файла. Также можно нажать «Открыть файл…» и выбрать `.json`.

### Другие браузеры и телефоны
Firefox, Safari и мобильные браузеры не дают странице записывать файлы. Там турнир хранится в браузере, а файл сохраняется вручную кнопкой **«Сохранить в файл»** и открывается кнопкой **«Открыть файл…»**. Сохранять после каждого тура — хорошая страховка.

## Возможности

- Ввод участников списком (можно вставить два столбца из Excel: имя и рейтинг).
- Жеребьёвка 1 тура по рейтингу: «корзинами» (ровные бои) или «подряд» (сильные с сильными).
- Швейцарская жеребьёвка 2–4 туров без повторных встреч.
- Ввод баллов, автоматический подсчёт мест и очков с делением мест при равных баллах.
- Ручная перестановка участников между боями до ввода результатов, отмена последнего тура.
- Турнирная таблица с дополнительными показателями, копирование для Excel. В клетке каждого тура мелко указаны места соперников по этому бою; наведение или нажатие подсвечивает их строки.
- Опция «Чётное число боёв» для удобства рассадки.
- Формирование финала из тройки лучших.
- Автосохранение каждого изменения в `.json` в выбранной папке и список турниров в ней.
- Итоговая таблица с кубковыми очками (1 — Ф, 2 — 25, 3 — 20, 4 — 17, 5 — 15, 6 — 14 … 19 — 1, дальше 0; поделённые места — среднее).
- Выгрузка в Excel (.xlsx) без интернета: каждый тур (сеткой по площадкам и списком), турнирная таблица, итог, весь турнир одним файлом. Файл загружается в Google Таблицы: «Файл → Импорт» или просто открыть .xlsx на Google Диске. Кнопки «Скопировать для таблиц» копируют с табуляцией — вставка в Google Таблицы ложится по ячейкам.
- Площадки и ведущие: бои раскладываются по площадкам, каждому бою подбирается ведущий из отдыхающих на той же площадке.

### Площадки и ведущие
На вкладке «Участники» до жеребьёвки:
- **Площадки:** количество (1–10), сколько боёв на одной площадке (1–4), названия (до 15 символов). Бои раздаются по кругу: при 10 боях и 5 площадках на первой — бои 1 и 6, на второй — 2 и 7 и т. д. Приложение покажет раскладку и предупредит, если мест меньше, чем боёв, или на площадке будет один бой.
- **Ведущие:** упорядоченный список участников; чем выше, тем выше приоритет. Добавляются по одному или вставкой списка имён.

Ведущий боя — участник с той же площадки, который в этом бою отдыхает (бой 1 ведёт кто-то из боя 6 и наоборот). Из подходящих выбирается тот, кто выше в списке; один человек ведёт не больше одного боя за тур; кто вёл в двух турах подряд, в следующем туре (и в финале после туров 3 и 4) автоматически не назначается — вручную выбрать можно, приложение пометит это. Сначала приложение старается обеспечить ведущим каждый бой. В карточке боя ведущего можно сменить вручную. В туре есть вид «По площадкам», кнопки «Пересчитать ведущих» и «Разложить заново по площадкам» (пока нет результатов). «Скопировать состав» группирует бои по площадкам и указывает ведущих. Ведущий финала — первый из списка, кто не играет в финале.

## Правила

### Размер боёв
Бои по 3. Если число участников N не делится на 3, остаток закрывается боями на 4 (`N mod 3` = 1 → один бой на 4, = 2 → два). Бои на 4 ставятся в низ таблицы.

| N  | Бои             |
|----|-----------------|
| 30 | 10 × 3          |
| 31 | 9 × 3 + 1 × 4   |
| 32 | 8 × 3 + 2 × 4   |

**Опция «Чётное число боёв»** (включается до жеребьёвки 1 тура). Если боёв получается нечётное число, 4 боя по 3 заменяются на 3 боя по 4, и боёв становится на один меньше. Бои по 4 остаются внизу таблицы.

| N  | Обычно                 | С опцией               |
|----|------------------------|------------------------|
| 33 | 11 × 3 (11 боёв)       | 7 × 3 + 3 × 4 (10)     |
| 34 | 10 × 3 + 1 × 4 (11)    | 6 × 3 + 4 × 4 (10)     |
| 35 | 9 × 3 + 2 × 4 (11)     | 5 × 3 + 5 × 4 (10)     |
| 30–32 | чётное и так (10)   | без изменений          |

### Очки за бой

| Место     | 1 | 2 | 3   | 4 |
|-----------|---|---|-----|---|
| Бой на 3  | 2 | 1 | 0   | — |
| Бой на 4  | 2 | 1 | 0,5 | 0 |

При равных баллах места и очки делятся поровну: 1–2 место — по (2 + 1) / 2 = 1,5; 2–4 место в бою на 4 — по (1 + 0,5 + 0) / 3 = 0,5.

### Тур 1 — посев по рейтингу
- **Корзинами** (по умолчанию). M — число боёв. Рейтинги 1…M — по одному в каждый бой, M+1…2M — змейкой в обратном порядке, 2M+1…3M — снова в прямом. Самые низкие рейтинги дополняют последние бои до четырёх.
- **Подряд**: 1-2-3, 4-5-6 и так далее.

### Туры 2–4 — швейцарская система
1. Таблица сортируется по очкам, затем по дополнительным показателям.
2. Бои собираются сверху вниз: первый бой получает лучшего из нераспределённых участников.
3. К нему подбираются соперники с минимальной разницей очков (штраф — сумма квадратов разниц очков в бою), с которыми он и они между собой ещё не играли. При равенстве — ближайшие соседи по таблице.
4. Если нижние бои без повторов не собираются, алгоритм откатывается и перебирает составы верхних боёв.
5. Если вариант без повторов не найден (на практике не встречалось), допускается минимум повторов, и приложение предупреждает об этом.

### Дополнительные показатели
Три показателя, порядок выбирается на вкладке «Участники». По умолчанию:
1. **Личная встреча.** Двое равных встречались в одном бою — выше тот, кто набрал в том бою больше баллов (даже если ни один не выиграл бой). Трое и больше — применяется, только если каждый играл с каждым: +1 за каждого из группы, кого обошёл в общем бою, −1 за каждого, кому уступил. Если хоть одна пара не встречалась, показатель пропускается и решает следующий. Равные баллы в общем бою преимущества не дают.
2. **Сила соперников** — средние очки всех соперников по боям. Берётся среднее, а не сумма, потому что в боях на 4 соперников больше.
3. **Сумма баллов**.

Если совпало всё — выше тот, у кого выше исходный рейтинг. Личная встреча срабатывает, только если стоит высоко: третьей по счёту она почти никогда не решает (до неё доходят единичные случаи), поэтому по умолчанию она первая. В старых турнирах «рейтинг» из списка убран, а личная встреча при открытии ставится первой.

## Разработка

```
src/engine.js      ядро: размеры боёв, подсчёт очков, таблица, жеребьёвка (без DOM)
src/xlsx.js        запись .xlsx без библиотек (ZIP + SpreadsheetML)
src/app.html       интерфейс; на место /*ENGINE*/ подставляются ядро и xlsx.js, на место <!--FONTS--> — шрифты
fonts/             шрифты Russo One, Golos Text, JetBrains Mono (SIL OFL 1.1), кириллица и латиница
icons/             иконки приложения
build.js           собирает index.html, dist/svoyak-zherebyevka.html, manifest.webmanifest, sw.js
index.html         приложение для GitHub Pages (PWA, офлайн)
dist/              автономный файл для пересылки
test/simulate.js   симуляция 4800 турниров (N = 25…48, оба режима разбивки) с проверкой на повторы
test/hosts.js      площадки и ведущие: раскладка, приоритет, без двойного ведения
test/tiebreak.js   личная встреча, порядок показателей, отдых ведущих после двух туров подряд
test/cup.js        кубковые очки и итоговая таблица
```

```
npm run build   # пересобрать всё после правок в src/
npm test        # симуляция; падает, если найдена повторная встреча
```

Результат симуляции: 4800 турниров, включая режим «чётное число боёв», — ни одной повторной встречи, жеребьёвка тура занимает до 0,1 с.
